# 开发路线

先让更新和同步足够可靠，再扩展界面与协作能力。以下是开发顺序，不是交付日期承诺。

## 0.4.4：发布与更新可靠性

- 将生产 Compose 与源码包分开，部署脚本不得覆盖域名、端口和数据卷配置。
- 构建失败、健康检查失败自动中止；保留上一镜像并验证一键回滚。
- 补两份不同 JS/CSS 构建之间的升级测试，以及子路径、多标签、离线和恢复网络测试。
- 更新安装必须完整缓存必要资源；评估迁移 Workbox precaching，保留用户确认和编辑保护。
- 清理开发依赖安全告警；随运行包附带新增依赖的完整许可声明。

验收：全新部署、保留数据升级、失败回滚均可自动复验；不同构建更新后无混合资源和白屏。

## 0.5：同步兼容与日期正确性

- 用真实后端跑 Playwright 登录、日程创建/修改、刷新回读、账号退出测试。
- 建立 Apple Calendar、Thunderbird 等客户端兼容矩阵，记录版本与复现步骤。
- 建立共享日期语料：夏令时、全天事件、跨时区、WKST、EXDATE 和单次实例修改。
- 用标准重复规则实现做差异测试；先适配现有数据，再决定是否替换自写展开逻辑。
- 扩展 Floating UI 到有边缘遮挡风险的浮层；保留键盘导航和焦点恢复。

验收：Web 与 DAV 双向修改一致；日期语料无未解释差异；已有事件无迁移损失。

## 0.6：日常使用体验

- 设置页按外观、日历、同步与 AI 整理分组，完善错误、加载和空状态。
- 用真实日程检查手机月/周视图、软键盘遮挡、横屏和触控操作。
- 统一动效参数与减少动态效果路径，不以动画延迟保存和关闭。
- 提供可辨认的同步状态和失败恢复入口，避免静默失败。

验收：核心流程可在手机完整完成；实体 iOS Safari 与 Android 浏览器各完成一轮验收。

## 后续候选

只读分享管理界面、联系人 Web 管理、多人协作。先明确权限与数据模型，再决定范围。
Web 通知提醒单独评估后台限制与可靠性，不在验证前承诺准时送达。

## 依赖选择原则

优先成熟开源实现，但必须检查许可证、维护状态、体积与兼容成本。
依赖打包并自托管，不增加运行时 CDN；稳定模块不为换库而重写。
